# Birak v2.1.0

This release closes the findings of the
[limited production readiness review](../audits/limited-production-readiness-20261022.md):
an S3 copy that emptied objects, gateways that opened on missing credentials,
files and subtrees whose loss replicated as deletions, and the operational gaps
around them. Startup now refuses several configurations that earlier releases
accepted with a warning; read **Upgrade from v2.0.4** before rolling out.

## Changes

### Data safety

- **S3 CopyObject copies.** It used to be handled as an empty PutObject, so
  `aws s3 cp`/`mv` between keys, or a copy onto itself to change metadata,
  replaced the object with zero bytes on every node. CopyObject and
  UploadPartCopy are now implemented: the source is read through the read
  fence, verified against its recorded checksum, staged next to the
  destination and published like a PUT, without holding the volume's commit
  lock. A self-copy changes nothing.
- **A file the daemon cannot read no longer takes the node down.** A root-owned
  0600 file used to keep the node unready forever and, after a restart, keep
  replication from starting while gateways accepted writes; an unreadable
  directory made startup fail. Such entries are now skipped and counted
  (`unreadable`), and are never treated as deleted.
- **Vanished subtrees are not replicated as deletions.** A directory on another
  filesystem below `sync_dir` now fails the sweep with an explicit error instead
  of being indexed: a nested disk that is not mounted looked like every file on
  it had been deleted. Deletions inferred from files missing on disk are budgeted
  by the new `sync.max_external_deletions` (1000 per 10 minutes): a larger group
  is held as a whole, the node turns unready and reports it, and nothing is
  replicated until the files return or the limit is raised. Gateway and peer
  deletions are not budgeted. Empty mount points are never removed.
- **An I/O error reading an indexed file quarantines it** and queues repair from
  peers, like a checksum mismatch (`birak_read_errors_total`).
- **Coarse filesystem timestamps** (NTFS, HFS+, SMB) no longer make a replica
  re-read every file on every sweep; mtimes are compared at the precision the
  volume stores.

### Security and configuration

- **Gateways fail closed.** An enabled gateway needs both credentials; with
  neither it starts only with the new `allow_anonymous: true`. One credential
  alone is always refused — an empty S3 secret or password used to be a value
  anyone could sign or log in with. Values starting with `changeme` (the
  examples in `.env.example`) are refused.
- **Clusters need an identity and a secret.** With `peers` configured,
  `node_id` and `cluster_secret` are required. Peer URLs must be `http(s)://`
  URLs; empty list items are dropped.
- **TLS for the peer API.** `tls_cert_file`/`tls_key_file` serve it over HTTPS,
  and `peer_ca_file` adds a private CA for verifying `https://` peers. Birak warns
  about `http://` peers outside private networks.
- A peer answering with this node's `node_id` is logged as an error and shown as
  `duplicate_node_id`; a peer URL that reaches the node itself is skipped; a node
  polling this one without being in its peer list is reported as an
  unconfigured poller.
- Presigned URLs are limited to 7 days and their credential date must match
  `X-Amz-Date`. Every spelling of `.birak` and of scratch prefixes is reserved
  on case-insensitive filesystems. HTTP UI errors no longer reveal filesystem
  paths.

### S3 behaviour

- Folder markers (`PUT prefix/` with an empty body) create the directory instead
  of a zero-byte file that broke later uploads below it.
- GET and HEAD evaluate `If-Match`, `If-None-Match`, `If-Modified-Since` and
  `If-Unmodified-Since` and answer `412` as XML without a misleading
  `Content-Length`; an unsatisfiable range answers `416 InvalidRange`. PUT and
  CompleteMultipartUpload honour `If-None-Match: *` and `If-Match` atomically.
- Errors that used to be `500` have S3 codes: `NoSuchBucket`, `KeyTooLongError`,
  `ParentIsObject`, `ObjectExistsAsDirectory`, `NameCollision`, `SlowDown`.
- A repeated CompleteMultipartUpload returns the original result; its body is
  checked against `Content-MD5`/`x-amz-content-sha256`. PUT, Complete and Copy
  return the same ETag as a later HEAD.
- Uploads whose declared length exceeds `max_upload_bytes` are refused before
  the body is read. Content-Type is derived from a safe set of extensions
  (`.apk` included); `X-Content-Type-Options: nosniff` is always sent.

### Operations

- Gateways and the peer API abandon transfers that make no progress for five
  minutes; slow transfers that keep moving are unaffected.
- Deleting a large tree through the HTTP UI or WebDAV proceeds in short batches
  instead of blocking every write on the node; content written into the tree
  meanwhile, or held open by a writer, is kept and the delete reports a
  conflict.
- HTTP UI uploads stream into the volume instead of `os.TempDir()`, publish
  nothing from a form that fails, and answer `413` over `max_upload_bytes`;
  large directories list several times faster with bounded memory; errors no
  longer reveal filesystem paths and invalid names answer `400`.
- Stopping drains open transfers for at most 8 seconds, in parallel, below
  Docker's default grace period.
- Metrics: `birak_disk_free_bytes`, `birak_disk_total_bytes`,
  `birak_gateway_requests_total`, `birak_build_info`,
  `birak_external_deletions_held`, `birak_read_errors_total`,
  `birak_peer_duplicate_node_id`, `birak_unconfigured_pollers`.
  `birak_last_scan_seconds` and `birak_peer_last_success_seconds` count from
  process start until the first success instead of being absent or zero.
  Families are grouped as the exposition format requires. `metrics_token`
  lets Prometheus scrape with a bearer token instead of the cluster secret.
- The access log adds duration, client address and `X-Forwarded-For`, and can be
  turned off with `access_log: false`; client aborts are no longer logged as
  errors.
- A new metadata database on a previously bound volume is logged as a warning;
  long sweeps log progress every 30 seconds.
- `birakd -version`, `version` in `/status`. A repeated reconcile pass on a full
  repair queue resumes where it stopped.
- The image includes `find-aws-chunked`, which lists objects that may still hold
  aws-chunked framing stored by v2.0.2.

### Deployment

- `docker-compose.yml` pins the release, requires every credential, passes the
  cluster secret and peer settings, rotates logs, waits 30 s on stop and has a
  health check. The nginx example streams downloads, keeps upstream connections
  alive and survives container recreation; a new HAProxy example routes several
  nodes by `/readyz`.
- CI pins every action by commit and govulncheck by version; `latest` moves only
  for the newest release.

## Upgrade from v2.0.4

Replication remains on protocol 4; nodes on v2.0.4 and v2.1.0 interoperate
during a rolling upgrade. Before starting v2.1.0, check the configuration — it
now refuses to start when:

- an enabled gateway has no credentials and no `allow_anonymous: true`, or only
  one of its two credentials;
- a credential, `cluster_secret` or `metrics_token` still starts with `changeme`;
- `peers` is set without `node_id` or without `cluster_secret`;
- a peer is not an `http://` or `https://` URL with a host;
- a directory below `sync_dir` is another filesystem (the node starts but stays
  unready until it is removed): move such disks out of `sync_dir` or combine
  them below the filesystem.

With the shipped compose file, `.env` must set `BIRAK_NODE_ID`,
`BIRAK_CLUSTER_SECRET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `HTTP_USERNAME` and
`HTTP_PASSWORD`.

Host-side deletions of more than 1000 files within 10 minutes now hold the
node unready until they are confirmed by a restart with a higher
`sync.max_external_deletions`. Plan bulk cleanups through a gateway, or raise
the limit for the operation.

CompleteMultipartUpload, PutObject and CopyObject now return the object's
size-and-time ETag instead of the multipart composite MD5; clients that compared
the Complete ETag with a locally computed composite value must use `HEAD`.

The metadata schema gains no new tables; completion records of multipart uploads
live in `sync_dir/.birak/multipart-completed/`. v2.0.4 starts on data written by
v2.1.0. Stop the node and back up consistent sync/meta directories, including
`.birak/storage-id`, before upgrading.

If objects were uploaded with aws-chunked bodies through v2.0.2, run
`docker exec birak find-aws-chunked` and compare the files it lists with their
originals.

## Validation

See the [fixes report](../audits/limited-production-fixes-20261022.md).

ACK still confirms local durable publication before asynchronous replication.
Deployment hardware, sustained cold-cache load and physical power loss require
separate operational validation; see [production readiness](../production-readiness.md).
