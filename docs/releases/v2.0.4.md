# Birak v2.0.4

Startup now fails explicitly when configuration or a serving component is
unavailable. Release builds use Go 1.26.10.

## Changes

- An explicitly supplied configuration file must exist and be readable. An
  absent `-config` option still permits environment-only configuration.
- Invalid nonempty numeric, duration and boolean environment overrides stop
  startup instead of silently retaining a default. Negative limits are validated,
  including the watcher debounce interval.
- Listener and other component failures reach the daemon's exit status. An
  occupied peer, S3, WebDAV, HTTP or SFTP port causes a nonzero exit and orderly
  shutdown of the other components.
- Components are constructed before background workers start, and SFTP shutdown
  waits for the accept loop before closing its connections.
- The module and Docker build use Go 1.26.10. Crash-injection tests now keep the
  child at its checkpoint until SIGKILL actually terminates it.

## Upgrade from v2.0.3

Replication remains on protocol 4; this patch does not change the metadata
schema. Check configured file paths and environment overrides before rollout:
settings that were previously ignored can now prevent startup. Normal SIGTERM
shutdown still exits successfully.

Existing S3 objects affected by the streaming upload issue fixed in v2.0.3 still
require comparison with their original checksums and reupload when necessary.
See the [v2.0.3 upgrade notes](v2.0.3.md) for that migration and storage backups.

## Validation

Local checks passed with Go 1.26.10: full macOS and Linux race suites, Linux
ENOSPC scenarios, vet, Windows cross-build, source and Docker-binary vulnerability
scans, real startup/exit probes, and four-node Docker fault acceptance. The scans
reported no reachable vulnerabilities. Tag CI requires Linux race/ENOSPC tests,
Windows build and Docker replication/TLS acceptance before publishing images.

ACK still confirms local durable publication before asynchronous replication.
Deployment hardware, sustained cold-cache load and physical power loss require
separate operational validation; see [production readiness](../production-readiness.md).

## Images

Images are published for `linux/amd64` and `linux/arm64`:

```sh
docker pull solkin/birak:2.0.4
```

Version aliases: `2.0`, `2` and `latest`.
