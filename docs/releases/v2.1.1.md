# Birak v2.1.1

A patch release on top of [v2.1.0](v2.1.0.md).

## Changes

- The checksum scrub saves the start position of its next cycle before it
  reports the finished one. For a moment, `/status` could show a completed
  cycle while the stored position still named that cycle's last file. No file
  was ever skipped: a restart in that moment only began with an empty cycle.
  The reordering removes an intermittent failure of
  `TestScrubRemembersItsPositionAcrossRestarts`, which blocked the first image
  build of v2.1.0 in CI.

## Upgrade from v2.1.0

Replication remains on protocol 4 and the metadata schema is unchanged; nodes
on v2.1.0 and v2.1.1 interoperate, and v2.1.0 starts on data written by
v2.1.1. Replace the image and restart node by node. Coming from v2.0.x, follow
the [v2.1.0 upgrade notes](v2.1.0.md#upgrade-from-v204) first: v2.1.0 refuses
configurations that earlier releases accepted.

## Validation

The tag workflow runs the full Linux race and ENOSPC suite, the Windows build,
source and binary vulnerability scans, and the four-node Docker fault and TLS
read acceptance before publishing images.

## Images

Images are published for `linux/amd64` and `linux/arm64`:

```sh
docker pull solkin/birak:2.1.1
```

Version aliases: `2.1`, `2` and `latest`.
