# Birak v2.2.0

A hardening and performance release on top of [v2.1.2](v2.1.2.md).

## Changes

### Security and hardening

- **Path and symlink safety across all gateways:** symlink targets (including
  dangling symlinks and symlink loops) are resolved consistently against
  `sync_dir` and never escape the root. Special files (FIFOs, devices) are
  opened non-blocking or rejected so a named pipe cannot stall a gateway worker.
- **Strict configuration validation:** unknown YAML fields, duplicate listener
  ports across gateways/sync API, whitespace-only credentials, and invalid
  multipart bounds (`min_part_bytes > max_part_bytes` against defaults) are
  refused at startup.
- **Gateway parity and limits:**
  - SFTP: `SETSTAT`/`FSETSTAT` enforce `max_upload_bytes` on truncate, rename
    of root is rejected, concurrent SFTP sessions per SSH connection are
    bounded (16), and half-configured credentials refuse login.
  - WebDAV: `DELETE`, `MOVE`, and `COPY` enforce descendant locks, directory
    copies skip scratch/reserved files, and `GET` sets
    `X-Content-Type-Options: nosniff`.
  - HTTP UI: JSON action bodies are capped at 64 KiB, client aborts are not
    logged as server errors, and directory listings enforce upload/visibility
    safeguards.
  - S3: virtual-host matching is case-insensitive and supports IPv6 `Host`
    headers.
- **Graceful shutdown and replication reliability:** HTTP/SFTP gateways and
  background sync loops drain cleanly on `SIGTERM` within the 8 s shutdown
  budget; repair backoff resets immediately when a newer version is enqueued;
  peer HTTP clients avoid leaking idle connections and handle large batch
  lookups (>1 000 names) cleanly.

### Performance

- **WebDAV `COPY` and multi-file commit lock offloading:** directory copies are
  staged, hashed on the fly, and pre-snapshotted outside the global commit lock;
  `watcher` batches multi-file local metadata writes into a single SQLite
  transaction (`PutLocalBatch`), cutting `s3_put_p99` under concurrent 20 MiB
  WebDAV `COPY` load from ~1.49 s to ~185 ms (`birak_commit_lock_worst_seconds`
  ~45 ms).
- **SQLite and scrub hot paths:** redundant `idx_files_name` dropped,
  `idx_repair_name` added, unchanged peer acks deduplicated within TTL, and
  replacement recovery skips redundant disk scans once clean.

### Build and CI

- `Dockerfile` uses `TARGETOS`/`TARGETARCH` for native cross-builds and injects
  the release version via `-ldflags` from the `VERSION` build arg.

## Upgrade from v2.1.x

Replication remains on protocol 4 and the metadata schema migrates additively;
nodes on v2.1.x and v2.2.0 interoperate. Before restarting, verify your YAML
config has no unknown keys, duplicate listener ports, or whitespace-only
credentials. Coming from v2.0.x, follow the
[v2.1.0 upgrade notes](v2.1.0.md#upgrade-from-v204) first.

## Validation

Verified with Go `-race`, `go vet`, Windows cross-build, the 4-node Docker
stress and 10k-object TLS read load suites, plus a 5-suite cross-protocol
Docker stand (corner cases, 4-protocol contention, 64-part S3 multipart stress,
real Linux 8 MiB tmpfs `ENOSPC`, and graceful `SIGTERM`).

## Images

Images are published for `linux/amd64` and `linux/arm64`:

```sh
docker pull solkin/birak:2.2.0
```

Version aliases: `2.2`, `2` and `latest`.
