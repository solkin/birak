# Birak v2.0.1

Birak returns to autonomous filesystem replication: every healthy node accepts
local reads and writes without a leader, voting membership or a quorum. Nodes
resume asynchronous synchronization after partitions and restarts.

## Breaking changes and upgrade

- Experimental quorum/Raft mode, its private generation storage and `birakctl`
  are removed. Only filesystem replication is supported. Quorum data directories
  cannot be opened as filesystem storage; there is no automatic conversion.
- Replication uses **protocol 4**. Upgrade all nodes together; older peers are
  explicitly rejected. Release builds pin **Go 1.26.9**; source builds require
  a patched supported Go toolchain.
- SQLite migrates automatically to extended clocks, portable namespace
  reservations and persistent replica admission. Back up consistent data and
  metadata, including `.birak/storage-id`, before upgrading. Keep pre-upgrade
  metadata for binary rollback.
- Case-only and Unicode-equivalent names cannot coexist. Resolve legacy aliases
  before upgrading if migration reports a namespace collision.

## Changes

- Conflict clocks can advance beyond int64 without blocking future writes.
- An empty replica stays unready until it applies observed state from a source;
  admission survives restarts and is not revoked when peers go offline.
- Restored unchanged bytes retain their recorded version when timestamps are
  lost, including publication recovered from a durable replica intent.
- S3 listings seek through SQLite's live-name index with bounded pagination and
  delimiter jumps, removing the daemon's old 100000-entry listing limit.
  Gateway PUT is indexed before ACK; direct filesystem input appears in LIST
  after watcher processing or a sweep.
- Sweeps batch metadata reads, file counts are cached by index version, and
  watcher/publication hashes are computed outside the shared commit lock.
- S3 supports configured TLS. Reader activity, bytes and revocations, admission,
  scrub budget and directory-fsync limitations are exposed as metrics.
- Docker acceptance now covers partitions, new and partial clones, SIGKILL,
  old backups, corruption/repair, and verified TLS APK/icon traffic.

## Validation

The first v2.0.0 tag was blocked by the vulnerability gate: CI selected the
exact Go 1.26.0 from `go.mod`, while local checks used a different toolchain.
v2.0.1 pins the patched Go 1.26.9 in both `go.mod` and Docker so CI and the
release image use the same version. No v2.0.0 release image was published.

Full race suites passed on macOS/APFS and Linux, including a separate Linux
ENOSPC volume. Vet, Windows cross-build and Docker build passed. A four-node
Docker fault stand passed with 500 MiB files. Native NTFS and physical power
loss are not established by these checks.

The local read stand used 500000 physical icon files, seven synthetic APK
payloads of 10–500 MiB, verified TLS, conditional GETs and concurrent uploads.
At the chosen profile it sustained **220.71 MiB/s APK**, around **992 icon
requests/s** during the active window, and **4.854 ms icon TTFB p99**, with no
hash/size/transport errors. Startup sweep fell from 22.39 to 5.18 seconds;
the last 1000 icon keys are now listed completely. A separate million-name
metadata check passed.

These are short warm-cache measurements inside a Linux Docker bridge, not a
24-hour production SLA. The macOS published-port path did not meet the APK
bandwidth target. Validate cold storage, external uplink and peaks for your
deployment. ACK confirms durable local publication before replication; losing
the sole surviving copy can still lose an acknowledged write.

## Images

The tag-triggered GitHub workflow tests the release before publishing Docker
images for `linux/amd64` and `linux/arm64`:

```sh
docker pull solkin/birak:2.0.1
```

Version aliases: `2.0`, `2` and `latest`.
